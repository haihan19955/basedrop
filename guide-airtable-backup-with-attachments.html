How to back up an Airtable base including attachment files

A CSV backup of Airtable loses your files because attachment links expire. How to build a backup that keeps records and files together.

Moving or archiving a base rather than backing it up? The Airtable export checklist covers all five pieces of a complete export — records, schema, attachments, views and automations.

Why CSV alone is not a backup

CSV export keeps values but attachment cells become expiring links, so the files are gone once the links expire. Airtable snapshots restore inside Airtable only and are not an offline copy.

Free method: CSV per table + files

  1. Download CSV for every table (one view per table showing all fields).
  2. Right away, download every attachment into folders named by record ID.
  3. Keep both in the same dated folder, e.g. 2026-10-23/Orders.csv and 2026-10-23/Orders/rec…/file.pdf.
The record ID is what lets you put files back on the right record later.

Back up the schema, not just the data

Records and files are only two thirds of a base. The third part is the schema: field types, single-select options, which fields link to which table, and which fields are formulas, rollups or lookups. A CSV holds none of that — restore from values alone and you get flat tables of text, with every link and formula to rebuild by hand.

Two free ways to capture it:

  1. API: call the Get base schema endpoint (GET /v0/meta/bases/{baseId}/tables) with a read token and save the JSON next to your CSVs. It lists every table, field type and option, and view names.
  2. By hand: for a small base, a one-page note per table — field names, types, and what each link field points at — is enough.
Be clear about the limit either way: no API-based export includes automations, interfaces or formula definitions; formulas are preserved as their computed values, not as formulas. BaseDrop Pro's full backup writes this schema JSON for you as schema.json, alongside the records and files.

Test the backup before you need it

A backup you have never opened is a hope, not a backup. After each run, pick one record at random and check it end to end from the backup folder — not from Airtable: open two of its files, find its row in records.csv, and follow one of its linked-record IDs to the matching row in the other table's CSV. If a file will not open or a row is missing, you still have time to re-run while the attachment links are fresh. Five minutes of checking is what turns an export into something you can restore from.

FAQ

Is this a full backup?

It keeps record data, field types and files. No API-based export includes automations, interfaces or formula definitions; formula results are saved as values.

Can I restore it?

Import records.csv into a new table, then re-attach files using the record ID folder names. Linked records are saved as record IDs. Automatic restore is not built in yet.
