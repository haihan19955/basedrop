Export Airtable attachments into folders (per record, client or project) for Drive or Dropbox

How to export Airtable attachments organised into folders by record or by a field like Client, ready to drop into Google Drive or Dropbox.

The goal

A folder tree like Client/Project/file.pdf rather than one flat pile, so you can drag it into Google Drive or Dropbox and colleagues find files without Airtable.

Free method: script with a folder column

Extend any CSV or API script so the save path is built from fields, e.g. {Client}/{record id}/{filename}. Strip characters that are illegal in file names (/ \ : * ? " < > |) and handle empty values.

Free method: automation straight to cloud storage

Make or Zapier can watch records and upload each attachment to a Drive/Dropbox folder named after a field. This is good for ongoing sync, but each file counts as operations on those platforms' plans.

With BaseDrop (Pro)

Set a folder template such as {field:Client}/{field:Project}; a "/" creates nested folders. Unzip the export into your synced Drive or Dropbox folder and the desktop client uploads it. BaseDrop does not connect to Drive or Dropbox accounts itself, so nothing else gets access to your cloud storage.

Landing in Google Drive

Export with a folder template, unzip the ZIP into a folder that Google Drive for desktop already syncs, and let the client upload the tree in the background. Keep folder names short — deep nesting inside a synced folder can run into Windows path limits — and avoid trailing spaces or periods in field values, which Windows silently trims from folder names.

Landing in Dropbox

The same pattern works with the Dropbox desktop folder: unzip into it and the client syncs the folders as they are. Dropbox replaces characters it does not allow and appends suffixes to conflicting file names, so a template with a counter keeps uploads conflict-free — see the renaming guide for the naming rules.

Sync conflicts and duplicates: read before re-exporting

Sync tools upload whatever lands in the folder, including your mistakes. Three habits keep the tree clean:

  • Re-exporting into the same synced folder uploads a second copy of everything and can create version conflicts. Export into a fresh, dated folder and swap it in instead.
  • If two people sync the same tree, agree on one owner for uploads, or the two clients will fight over the same files.
  • If colleagues need the individual files, unzip locally before syncing rather than syncing the ZIP itself — and remember that sync is not backup: a deletion syncs too.
