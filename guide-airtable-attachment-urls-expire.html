Airtable attachment URLs expire: why, and how to fix it

Airtable attachment links from CSV exports and the API stop working after a few hours. What changed, what still works, and how to keep permanent copies.

What is happening

Airtable serves files through expiring download URLs on airtableusercontent.com. Airtable says these links expire after a short time for security reasons, while the attachment viewer URL (opened inside Airtable) keeps working for collaborators (Airtable: attachment URL behavior). Old CSV exports, emails and websites that embedded those links break.

Fix 1: share inside Airtable

For colleagues who have base access, open the attachment, copy the viewer URL from the address bar. It does not expire while the attachment exists.

Fix 2: copy files to permanent hosting with an automation

For websites and external partners, use an automation (Airtable automations with a script, Make or Zapier) that, when a record changes, downloads the file while the link is fresh and uploads it to Google Drive, S3 or Cloudinary, then writes the permanent link back to a URL field. Community examples: Cloudinary + Zapier/Make.

Fix 3: download the files themselves

If you just need the files (archive, hand-off, migration), fetch them in the same session you read the links. Any of the free methods in this guide work; BaseDrop does it in one pass, so a link never sits long enough to expire.

FAQ

How long do Airtable download links last?

Airtable describes them as expiring after a short time and changes may happen; plan for a few hours and never store them.

Can I make a link permanent?

No. Store a copy of the file elsewhere and keep that URL instead.
